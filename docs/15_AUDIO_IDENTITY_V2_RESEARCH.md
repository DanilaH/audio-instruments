# 15 — Audio Identity v2 research

Status: **active research / comparative prototyping**.

This pass exists because `Reference Instrument v1` failed an important portfolio-level test: it converged too closely on the existing Hardware Testing visual grammar. The next Audio identity must be recognizably different from Hardware Testing before the viewer reads the page title.

## Hard constraint

> If a visual system can be transferred almost unchanged to Mouse Test, Keyboard Test or Controller Test, it is not specific enough for Browser Audio Lab.

The next identity must grow from relationships that are genuinely native to sound: time, frequency, amplitude, phase, stereo/spatial position, playback/recording state and listening thresholds.

## Research findings

### 1. Stereo is a shape, not only two labels

Stereo vectorscopes/goniometers plot the relationship between left and right channels on an x-y field. A mono signal tends toward a vertical line; width, asymmetry and phase relationships change the geometry. This is useful because the visual form is generated by the signal relationship itself rather than by decorative UI chrome.

Reference:
- iZotope Insight vectorscope documentation: https://www.izotope.com/en/content/download/77707/file/izotope-insight-help-documentation.pdf

### 2. Audio analysis naturally creates layered coordinate systems

Spectrograms are time-frequency representations where energy is encoded through brightness/colour. Tools such as Sonic Visualiser also combine time rulers, spectrogram layers, peak-frequency information, spectra, annotations and alternative colour mappings. Praat similarly layers waveform, spectrogram, pitch, formants and intensity around a shared time axis.

References:
- https://sonicvisualiser.org/doc/reference/4.5.2/en/
- https://praat.org/manual/Intro_3_1__Viewing_a_spectrogram.html
- https://praat.org/manual/Intro_7__Annotation.html

### 3. Hearing thresholds already have an audio-native map

Audiograms plot frequency against loudness / hearing threshold. The visual language is not a generic dashboard: the coordinate system itself encodes the listening task.

Reference:
- UHCW NHS, Understanding your hearing test results: https://www.uhcw.nhs.uk/download/clientfiles/files/Patient%20Information%20Leaflets/Clinical%20Diagnostic%20Services/Audiology/Understanding%20your%20hearing%20test%20results.pdf

Browser Audio Lab must not imply that its Hearing Frequency Test is a diagnostic audiogram, but the underlying idea — hearing as a frequency-positioned observation rather than a stack of cards — is useful.

### 4. Audio editing makes time an interaction surface

Waveform editors use playheads, point labels, region labels, selections, split lines and loop ranges. Controls are attached to moments or spans in time rather than arranged only as generic forms.

Reference:
- Audacity navigation / marking documentation: https://manual.audacityteam.org/man/navigation_tips.html
- Audacity label tracks: https://manual.audacityteam.org/man/label_tracks.html

### 5. Graphic scores show that sound can be structured spatially without looking like a DAW

Cornelius Cardew's *Treatise* uses lines, circles and geometric structures as musical notation without a conventional key. The lesson is not to imitate the artwork. The useful principle is that a page can behave like a score whose geometry is tied to sonic progression rather than to a component library.

References:
- British Music Collection: https://britishmusiccollection.org.uk/score/treatise
- Beyond Notation overview: https://www.beyondnotation.com/

### 6. Spatial audio is naturally listener-centred

Surround layouts are represented around a listening position. Dolby's setup diagrams explicitly organize channels around the listener / sweet spot and show angular relationships between speakers.

Reference:
- https://www.dolby.com/en-gb/about/support/guide/dolby-atmos-speaker-setup/

## What this research rejects

The next pass must not fall into another obvious preset:

- Hardware Testing-style neutral utility shell;
- generic DAW / plugin dark panel;
- neon waveform on black as the whole identity;
- retro hi-fi / analog equipment cosplay;
- Teenage Engineering imitation;
- brutalism / terminal / monospace anti-AI preset;
- editorial serif / cream / paper texture anti-AI preset;
- generic SaaS cards, pastel gradients and floating blobs.

## Comparative prototype directions

The next prototype deliberately creates three systems that are structurally different, not three palettes applied to one layout.

### Direction A — Stereo Field

**Thesis:** audio is a spatial field whose geometry changes with channel routing, width, phase and movement.

Primary sources:
- vectorscope / goniometer;
- stereo balance / correlation;
- listener-centred spatial audio diagrams.

Visual grammar:
- one dominant spatial field rather than left-card/right-card composition;
- L/R/center/channel targets exist inside the field and can become direct controls;
- trajectories, vectors, arcs and phase geometry communicate state;
- controls live at the boundary of the field rather than inside nested cards;
- channel colour is allowed only where it encodes a real channel or overlap.

Prototype stress cases:
- Headphone Test: channel targets become the core interaction;
- Spectrum Analyzer: spectral display lives in the same continuous signal field rather than inside a utility panel;
- Hearing Frequency Test: frequency progression becomes a spatial trajectory instead of a large number plus cards.

Failure mode to avoid: looking like a generic dark audio plugin.

### Direction B — Temporal Score

**Thesis:** audio tools are sequences of events, regions and listening decisions laid out along time.

Primary sources:
- waveform-editor playheads / regions / markers;
- tape / edit notation logic;
- graphic-score composition.

Visual grammar:
- horizontal progression is the main organizing axis;
- current state is a playhead / event marker, not a coloured card;
- labels behave like annotations attached to moments or ranges;
- controls are embedded near the event they affect;
- asymmetry and whitespace are permitted when they follow the sonic sequence;
- the page can feel like a living score rather than a dashboard.

Prototype stress cases:
- Headphone Test: burst / phase / sweep modes become different score segments;
- Spectrum Analyzer: current spectral slice and scrolling time-frequency layer share a timeline;
- Hearing Frequency Test: each prompted tone is an event in a visible listening sequence, with answers recorded as marks.

Failure mode to avoid: becoming an art poster or editorial anti-AI gimmick.

### Direction C — Acoustic Map

**Thesis:** audio is a terrain defined by frequency, time, amplitude and threshold.

Primary sources:
- spectrograms / cochleagrams;
- audiograms;
- contour / heat-map thinking;
- spectral peak and formant overlays.

Visual grammar:
- large continuous maps instead of card collections;
- axes and contours carry real meaning;
- colour exists mainly inside data / signal fields;
- annotations sit on top of the map like coordinates, peaks, thresholds or observations;
- controls remain visually quiet and do not compete with the data surface.

Prototype stress cases:
- Headphone Test: L/R energy is represented as a binaural field rather than device illustration;
- Spectrum Analyzer: spectrogram / spectrum become the native identity rather than one mode inside a panel;
- Hearing Frequency Test: the session becomes a non-diagnostic frequency observation map.

Failure mode to avoid: scientific-dashboard density or a generic data-viz product.

## Shared prototype rules

All three directions use the same three real tools:

1. Headphone Test
2. Spectrum Analyzer
3. Hearing Frequency Test

The comparison is accepted only if each direction can produce coherent versions of all three.

For the first comparison:

- desktop 1366×768 is the primary art-direction frame;
- core tool must appear in the first viewport;
- no production merge;
- functionality is preserved where practical, but visual-system exploration has priority over production polish;
- no new medical / measurement claims;
- no decorative waveform, scale, contour or phase geometry unless it represents a real concept from the tool;
- layouts should reserve space for dynamic states rather than introducing new layout shifts.

## Evaluation matrix

Each direction is scored on:

1. **Hardware distance** — recognizably different from Hardware Testing at a glance.
2. **Audio specificity** — difficult to transfer to a mouse/keyboard tester without losing meaning.
3. **Non-slop identity** — neither generic AI-SaaS nor generic anti-AI styling.
4. **Tool-first composition** — useful instrument appears immediately.
5. **Scalability** — can plausibly cover all 16 audio tools.
6. **State stability** — dynamic changes can occur inside a stable frame.
7. **Measurement honesty** — visual intensity / geometry does not imply unsupported precision.
8. **Accessibility** — colour is not the sole state carrier and controls remain legible / operable.

## Adoption rule

Do not choose the most fashionable screenshot.

Choose a direction only if its visual grammar explains why Browser Audio Lab looks the way it does and if the same grammar remains useful across playback, spatial, recording, hearing and analysis tools.

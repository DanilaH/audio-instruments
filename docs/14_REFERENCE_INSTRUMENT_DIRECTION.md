# 14 — Reference Instrument Design Direction

Status: **REJECTED after prototype review** on `prototype/reference-instrument-v1`.

## Prototype review outcome

The research principles remain useful, but the rendered `Reference Instrument v1` visual language is **not approved for production**.

The prototype converged too closely on the existing Hardware Testing product family. The collision is structural, not just a matter of color:

- compact functional page heading;
- neutral technical canvas;
- thin grey borders and separators;
- small radii;
- restrained signal accent;
- dense utility controls;
- two-zone / two-column instrument shell;
- measurement-first technical hierarchy.

That grammar is already appropriate to Hardware Testing. Reusing it for Browser Audio Lab would make the portfolio feel like one design system reskinned for another domain instead of two independently authored products.

Therefore **do not continue polishing this prototype into production** and do not treat `Reference Instrument` as the approved Audio identity.

What survives from the research is the method, not the skin:

- visual decisions should have provenance;
- color should carry deliberate meaning rather than generic atmosphere;
- decorative UI chrome should not dominate the tool;
- data and interaction should create identity where possible;
- avoid both generic AI-SaaS and generic anti-AI presets;
- secondary technical detail should not overwhelm the core job;
- dynamic layouts should remain stable.

The next art-direction pass must add a new explicit constraint:

> **Browser Audio Lab must be recognizably different from Hardware Testing at a glance, even before reading the title or seeing the specific tool.**

The next research/prototype direction should therefore avoid using the following as its primary identity:

- grey instrument chassis;
- generic laboratory / bench-equipment framing;
- compact neutral utility shell as the dominant composition;
- teal/green signal accent on a mostly grey interface;
- the same border/radius/density vocabulary as Hardware Testing.

This document is retained as a record of the rejected exploration so future work does not accidentally repeat it.

---

## Original research thesis retained for reference

The original prototype explored the idea that Browser Audio Lab should look like a family of modern digital reference instruments rather than a website decorated with audio widgets. Reference families included professional measurement hardware, Nagra-class audio equipment, calibration media, test-card culture and modern analytical audio software.

The useful lesson was that design decisions should come from the product domain rather than from trend inversion. The failed lesson was assuming that "technical instrument" itself could supply the identity. In this portfolio, that territory is already occupied by Hardware Testing.

Future exploration must derive its character from qualities that are more specifically **audio-native**: temporal behavior, rhythm, stereo space, phase, harmonic structure, waveform topology, recording/playback semantics, acoustic notation, signal transformation and listening culture — without degenerating into music-player skeuomorphism, DAW cosplay, neon waveform decoration or generic creative-tool styling.
